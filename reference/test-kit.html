@chamvi/test-kit ​

Test helpers for chamvi: a controllable clock, the repository and workspace contract suites, a git fixture and an in-process fake GitHub.

bash
npm install --save-dev @chamvi/test-kit @chamvi/core vitest

@chamvi/core and vitest are peer dependencies; the workspace contract takes any IWorkspace of @chamvi/sandbox, typed structurally (ContractWorkspace), so the kit does not depend on @chamvi/sandbox.

describeRepositoryContract ​

ts
function describeRepositoryContract(
    create: (clock: ControllableClock) => IStore | Promise<IStore>,
): void;

Registers the Vitest suite every IStore implementation must pass. create is called once per test with a fresh ControllableClock and must return a fresh, empty store that uses that clock for every expiry decision.

ts
// test/unit/store.spec.ts
import { createMemoryStore } from '@chamvi/core';
import { describeRepositoryContract } from '@chamvi/test-kit';

describeRepositoryContract((clock) => createMemoryStore({ clock }));

See Writing a Repository for what the suite covers.

describeWorkspaceContract ​

ts
function describeWorkspaceContract(name: string, factory: WorkspaceContractFactory, options?: WorkspaceContractOptions): void;

type WorkspaceContractFactory = (input?: { runId?: string }) => Promise<ContractWorkspace>; // every IWorkspace is a ContractWorkspace
type WorkspaceContractOptions = { find?: (runId: string) => Promise<ContractWorkspace[]> };

Registers the Vitest suite every sandbox provider's workspaces must pass: argv exec and exit codes (127 for a command that cannot start), stdin, cwd and path escapes (../.., /etc, an empty path, a NUL byte), the 64 KiB output caps under a flood, a process-group kill on timeout that takes a backgrounded grandchild with it, abort, UTF-8 files and their size cap, and dispose during an exec. factory returns a fresh, repo-less workspace per test (of input.runId when given); the suite disposes it. With find (a second provider instance's find, like a restarted process) it also creates a workspace, drops the handle and expects find to return it with its files. It runs real processes with short real timeouts, not a ControllableClock.

ts
describeWorkspaceContract('local', () => createLocalSandbox().create({ runId: 'r1' }));

createFakeGithub ​

ts
function createFakeGithub(options: FakeGithubOptions): FakeGithub;

type FakeGithubOptions = { appId: string; slug?: string; clock: IClock };

An in-process GitHub for createGithubApp({ fetch: fake.fetch, privateKey: fake.privateKey }) from @chamvi/github. It generates an RSA key pair, verifies App JWTs (RS256, iss, at most 600 s) on /app* and installation tokens (valid one hour on clock) on every other route, and answers 404 for unknown routes. Issues, comments, labels, pull requests, contents and releases live in mutable maps (issues, comments, labels, pulls, files, releases, keyed owner/repo#number or owner/repo); the comment list honours since (by updated_at) and paginates with a link header. Repositories (repositories, a missing one synthesized public with default branch main), the App's installations (appInstallations, GET /app/installations with the App JWT), check runs and commit statuses (checkRuns, statuses, keyed owner/repo@<sha>, the combined status state derived) and branch protection and rules (branches, rules, keyed owner/repo:<branch>, unprotected when missing) back the repository, issue and pull request lists, issue and pull request creation (the next number, as the bot; 422 for a second open pull request of one head and base), the merge (409 when sha is not the head, 405 once merged or not mergeable) and GET /installation/repositories (the installations entries of the token's installation).

MemberPurpose
fetchThe fake fetch to hand to createGithubApp
privateKey, publicKeyThe App's key pair (PKCS#1 PEM, KeyObject)
requestsEvery request (method, path, query, body, authorization), in order
jwtClaims, tokensIssued, tokenInstallationsThe accepted JWTs and the issued installation tokens
route(method, path, handler)Adds or overrides a route (:name one segment, *name the rest)
failNext(method, path, status)The next matching request answers status, once

A request whose signal aborts, also while a route handler is pending, rejects with the signal's reason, as Node's fetch does. It never touches the network.

ControllableClock ​

ts
class ControllableClock implements IClock {
    constructor(start?: Date); // default new Date(0)
    now(): Date;
    setTimeout(fn: () => void, ms: number): { clear(): void };
    advance(ms: number): void;
}

Time moves only through advance(ms), which fires every timer due within the window in order, including timers scheduled by fired callbacks. The keepAlive timer option has no meaning without a real event loop and is ignored.

ts
const clock = new ControllableClock(new Date('2026-01-01T00:00:00Z'));
const store = createMemoryStore({ clock });

await store.locks.acquire('job', 'replica-a', 1_000); // true
await store.locks.acquire('job', 'replica-b', 1_000); // false, held by replica-a

clock.advance(1_000); // a lease expires at exactly T + ttlMs
await store.locks.acquire('job', 'replica-b', 1_000); // true

Pass the same clock to the store and to the engine (new Engine({ ..., clock })) to test claim leases, run timeouts and approval expiry without real timers.
