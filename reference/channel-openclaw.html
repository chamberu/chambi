@chamvi/channel-openclaw ​

The OpenClaw channel. The public API of packages/channel-openclaw/src/index.ts.

bash
npm install @chamvi/channel-openclaw @chamvi/core --save

@chamvi/core is a peer dependency; the channel uses the global fetch. See OpenClaw for the setup.

openclawChannel ​

ts
function openclawChannel(options: OpenclawChannelOptions): IChannel; // out only, name default 'openclaw'

const OPENCLAW_CHANNEL_NAME: 'openclaw';
const DEFAULT_HOOKS_PATH: '/hooks';
const OPENCLAW_TIMEOUT_MS: 30_000;
const OPENCLAW_REQUEST_ERROR_CODE: 'openclaw_request';
const MESSAGE_BODY_MAX_LENGTH: 8_000;
ts
/** Where OpenClaw delivers the agent turn's answer; both `channel` and `to` are concrete. */
export type OpenclawDelivery = {
    /** E.g. `telegram`, `slack`, `whatsapp`; `last` is refused by OpenClaw for hooks. */
    channel: string;
    /** The default recipient on that channel (chat id, user, number); a non-empty address overrides it. */
    to: string;
    /** Selects one of several accounts of the channel. */
    accountId?: string;
};

/** What `approvalUrl` gets: ids only, never a token. */
export type OpenclawApprovalRef = {
    runId: string;
    approvalId: string;
    agent: string;
};

export type OpenclawChannelOptions = {
    /** The channel name; default `'openclaw'`. A second instance needs its own. */
    name?: string;
    /** The OpenClaw gateway, e.g. `http://openclaw:18789`; a base path is kept. */
    baseUrl: string;
    /** OpenClaw's `hooks.token` (a hook-dedicated token, not the gateway token). */
    hooksToken: string;
    /** OpenClaw's `hooks.path`, default `/hooks`. */
    hooksPath?: string;
    /** The OpenClaw agent that phrases the message (must be in `hooks.allowedAgentIds` when set). */
    agentId?: string;
    deliver: OpenclawDelivery;
    /**
     * A link to the approval in the chamvi UI, e.g.
     * `https://<app>/ui/approvals?run=<runId>&approval=<approvalId>`, where the
     * signed-in owner answers it; it carries no token.
     */
    approvalUrl?: (ref: OpenclawApprovalRef) => string;
    /** Bound of one send; default `OPENCLAW_TIMEOUT_MS` (30 s). */
    timeoutMs?: number;
    clock?: IClock;
    fetch?: typeof globalThis.fetch;
};

/** The body of `POST <hooksPath>/agent`. */
export type OpenclawHookBody = {
    message: string;
    name: 'chamvi';
    agentId?: string;
    deliver: true;
    channel: string;
    to: string;
    accountId?: string;
};

Throws InvalidAgentDefinitionError for an invalid name, an empty hooksToken, agentId, deliver.to or deliver.accountId, a deliver.channel that is empty or last, a baseUrl that is no absolute http:/https: URL or carries credentials, a query or a hash, a hooksToken that fetch could not send as a header (a control character, a character above U+00FF, surrounding whitespace), a hooksPath that does not start with / or is / (trailing slashes are dropped, so /hooks/ posts to /hooks/agent), an approvalUrl that is no function and a timeoutMs that is no positive integer.

ts
const openclaw = openclawChannel({
    // the OpenClaw gateway, reachable from the app
    baseUrl: 'http://openclaw:18789',
    // OpenClaw's hooks.token, not the gateway token
    hooksToken: process.env.OPENCLAW_HOOKS_TOKEN ?? '',
    // placeholders: the channel and recipient of your OpenClaw setup
    deliver: { channel: '<channel>', to: '<recipient>' },
    // optional: a link to the approval in the UI; a message never carries the token
    approvalUrl: ({ runId, approvalId }) => `https://chamvi.example/ui/approvals?run=${encodeURIComponent(runId)}&approval=${encodeURIComponent(approvalId)}`,
});

const engine = new Engine({
    store: new MemoryStore(),
    agents,
    // tools reach it with ctx.channels.findOneOrFail('openclaw')
    channels: [openclaw],
});

Tools send through it with ctx.channels.findOne('openclaw') (emit(), approve()); the address is the recipient, and an empty one sends to deliver.to:

ts
export const deploy = defineTool({
    description: 'Deploy the current release.',
    inputSchema: z.object({ env: z.enum(['staging', 'prod']) }),
    execute: async ({ env }, { context }) => {
        const openclaw = context.channels.findOneOrFail('openclaw');
        // without an address both go to deliver.to (the channel's defaultAddress)
        const { approved } = await openclaw.approve({ title: `Deploy to ${env}?` });
        if (!approved) return 'the owner said no';
        await openclaw.emit({ body: `Deployed to ${env}.` });
        return `deployed to ${env}`;
    },
});

The request ​

out(message, address) sends one POST <baseUrl><hooksPath>/agent:

PartValue
authorizationBearer <hooksToken>
idempotency-keymessage.key (an emit's content-addressed key, <runId>:<approvalId> for an approval), or sha256:<hex> of it when it is longer than 256 characters or holds anything but visible ASCII
bodyOpenclawHookBody: { message, name: 'chamvi', agentId?, deliver: true, channel, to, accountId? }; to is the address, or deliver.to for an empty one

The message is deterministic for one key (no clock value, no random id), so a resend after a lost response is byte-identical and OpenClaw replays it:

chamvi message. Relay it to the user; keep every link and id exactly as written.

<title>

<body, cut to MESSAGE_BODY_MAX_LENGTH characters>

Agent: <agent>
Run: <runId>

Expires: <expiresAt ISO>
Approve or deny: <approvalUrl({ runId, approvalId, agent })>

The title and body appear when the message has them. The last block is sent for approvals only; without approvalUrl its last line reads Answer it in the chamvi UI or through POST /runs/:id/approve. instead. approvalUrl gets the run id, the approval id and the agent. A cut body ends with … (cut, <n> more characters) and never splits a surrogate pair.

Failures ​

Any 2xx resolves. Every other status throws a ChamviError with code openclaw_request and the message OpenClaw <status>: <response text> (plus (retry after <value>) for a Retry-After header); a network failure throws OpenClaw request failed: <message> (<cause message>) (undici keeps the detail, such as ECONNREFUSED or ENOTFOUND, in cause), a send that takes longer than timeoutMs OpenClaw did not answer within <ms>ms. (the timer runs on the clock and aborts the fetch); an abort of the caller's signal (the run cancelled, the engine draining) rejects with its reason. The response text and the network failure message are cut to 500 characters after the hooks token was replaced by [redacted], so an endpoint that echoes the request never puts it into onError. A failed emit() is a tool error and records nothing; a failed approval message is re-sent by tick().

Module ​

ts
// @chamvi/channel-openclaw/module, needs @chamvi/app
function openclawModule(options?: OpenclawModuleOptions): IModule; // name 'chamvi:channel:<name>', default name 'openclaw'

Reads OPENCLAW_BASE_URL, OPENCLAW_HOOKS_TOKEN, OPENCLAW_CHANNEL, OPENCLAW_TO (required), OPENCLAW_HOOKS_PATH, OPENCLAW_AGENT_ID and OPENCLAW_ACCOUNT_ID from options.env ?? process.env when it is called (options win), defaults approvalUrl to the dashboard link from CHAMVI_PUBLIC_URL and contributes the channel to the app's channels (AppToken.CHANNELS), so the engine registers it and tools reach it with ctx.channels.findOne(name). @chamvi/app is an optional peer: the main entry never imports it.
