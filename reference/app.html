@chamvi/app ​

Boots chamvi agents as an app. The public API of packages/app/src/index.ts and its subpath entries; see Apps & Modules for the concepts.

bash
npm install @chamvi/app ai typeorm pg

ai, typeorm and pg are peer dependencies. The provider packages (@ai-sdk/anthropic, @ai-sdk/openai, @ai-sdk/openai-compatible, @ai-sdk/google, @ai-sdk/mistral, @ai-sdk/xai) and the @authup/* packages behind @chamvi/app/authup are optional peers. The other optional modules ship with their feature packages (@chamvi/github/module, ...), so @chamvi/app depends on none of them. The main entry re-exports @chamvi/core and agentPermission, Permission and the Authenticator, Principal, HttpRoute, HttpRouteContext, HttpRouteRequest, HttpRouteResult and StaticToken types of @chamvi/http.

createApp ​

ts
function createApp(options: AppOptions): IApp;
function isApp(value: unknown): value is IApp;

const APP_BRAND: unique symbol; // Symbol.for('chamvi.app')

Synchronous and side-effect free. agents may be omitted or empty: the agents can come from an agents folder, and an app with no agent at all still starts (a warning); app.agents holds only the code agents, the live set is engine.listAgents(). Throws InvalidAgentDefinitionError for options that are no object or whose agents is no array, a module list entry that is no IModule and for two modules of one name (a built-in's name included: list one module to replace a built-in). isApp checks the brand, so an app of another installed copy matches.

import type { Agent, ModelRef } from '@chamvi/core';
import type { AgentIssue } from '@chamvi/http';
import type { IModule } from 'orkos';
import type { Env } from '../env/types.ts';
import type { ModelProviders, ProviderConfig } from '../models/types.ts';
import type { APP_BRAND } from './constants.ts';

export type AppOptions = {
    /** The code agents; may be omitted or empty when CHAMVI_AGENTS_DIR names an agents folder. */
    agents?: Agent[];
    /** Extra modules; one named like a built-in (`ModuleName`) replaces it. */
    modules?: IModule[];
    /** The default model of agents without one; CHAMVI_MODEL and the config file win. */
    model?: ModelRef;
    /** Named providers model strings resolve through; env and the config file win per field. */
    providers?: Record<string, ProviderConfig>;
    /** AI SDK providers by id; they win over every provider setting for their ids. */
    models?: ModelProviders;
};

export type AppLifecycleOptions = {
    /** Default `process.env`. */
    env?: Env;
};

export type AppStartOptions = AppLifecycleOptions & {
    dev?: boolean;
};

export type AppCheckOptions = AppStartOptions;

export type AppCheckResult = {
    /** The agent folders' load issues (`AGENT_ISSUES`), one per folder; empty without an agents dir. */
    issues: AgentIssue[];
};

export type AppRunJobOptions = AppLifecycleOptions & {
    agent: string;
    /** Cron subscription id; optional when the agent has exactly one cron subscription. */
    subscription?: string;
};

export type AppRunJobResult = {
    runId?: string;
    status: string;
    exitCode: 0 | 1;
};

/**
 * An app: built by createApp, run once by one of `start`, `runJob` or
 * `migrate` (a second lifecycle rejects with `app_in_use`).
 */
export interface IApp {
    readonly [APP_BRAND]: true;
    /** The code agents (createApp's `agents`); folder agents are in the engine's live set. */
    readonly agents: readonly Agent[];
    /** Sets every module up; resolves once the HTTP server listens. */
    start(options?: AppStartOptions): Promise<void>;
    /**
     * Memoized: aborts the lifecycle, waits for it, tears every module down;
     * rejects with `app_stop_failed` when anything was reported meanwhile.
     */
    stop(): Promise<void>;
    /** Fires one cron subscription once and waits for its run (no channel started, no HTTP). */
    runJob(options: AppRunJobOptions): Promise<AppRunJobResult>;
    /** Migrates the store (DATABASE_URL required) and closes it. */
    migrate(options?: AppLifecycleOptions): Promise<void>;
    /**
     * The start path up to its start steps (`context.check`, mode `start`):
     * config, store connection, model settings, every module's setup and
     * onReady and the agent folders' load and checks, then the teardown; no
     * engine or channel start, no server, no run, no store write (no
     * migration, marker, cancel or lock). Resolves the agent folders' load
     * issues; the lifecycle hooks `engineCreated` and `drained` run, never
     * `started` or `stopping`. A configuration error rejects (`invalid_agent_definition`), a
     * store failure with its own code (`store_not_migrated`, a connection
     * error). The app's one lifecycle, like start().
     */
    check(options?: AppCheckOptions): Promise<AppCheckResult>;
}

runJob resolves exitCode: 0 for a completed, waiting, skipped, queued-behind-an-approval or signal-interrupted run, 1 for failed or cancelled.

Errors ​

ChamviError codes in APP_ERROR_CODE:

CodeWhen
app_stoppedThe lifecycle's abort reason once stop() was called; a start stopped while setting up rejects with it
app_in_useA second start, runJob or migrate on the same app
app_stop_failedstop() (or a job's teardown) after one or more teardown errors, each logged

Configuration errors (a malformed or missing variable, a model string naming a provider that is not configured, an agent with no model and no default, a duplicate module name) are core InvalidAgentDefinitionErrors; they name the variable and never echo its value.

HTTP intake and execution ceilings ​

httpModule({ channelRateLimits, trustProxy }) forwards the channel request policies to createHttpApp(). Configure a mounted channel by its exact name, with { max, windowMs? } for a separate per-client bucket or false to disable only that channel's intake limiter. No environment variable is added for this setting. Trust only known proxy sources.

CHAMVI_MAX_CONCURRENT_RUNS is the local engine ceiling. Agent and subscription concurrencyMaxRuns?: number | false add nested shared-store ceilings; see Concurrency.

Listing one of them in createApp({ modules }) replaces the default instance. engineModule() reads the model settings in setup (start and job mode: env over the config file over createApp({ model, providers }), models over all for its ids), refusing every settings issue at once (The model settings have <n> issue(s): and one line each), imports the provider packages the settings need and passes the default model and the resolver to the Engine as model and models, which checks every agent when it is registered; it never reads or sets the AI SDK's global default provider. agentsModule() (no options) reads CHAMVI_AGENTS_DIR, else takes ./agents when it is a directory: in start and job mode its onReady loads every folder into the engine before any start step (a dir that is no directory is InvalidAgentDefinitionError), and in start mode a lifecycle hook polls the dir from started until stopping; it registers AppToken.AGENT_ISSUES, which the http module passes on as agentIssues. A folder agent passes every AppToken.AGENT_CHECKS contribution (the scheduler module's assertSchedulable, the http module's assertMcpRunTool unless mcp: false) and the engine's registration checks in putAgent (every subscription names a registered channel, the model resolves through the app's providers) before it is registered; a refusal is a load issue, never a failed boot. Only start mode removes an agent whose marker has no folder; a job never does. Without a dir it only refuses an app without agents.

Each factory reads options.env ?? process.env when it is called and throws InvalidAgentDefinitionError naming a missing or malformed variable. Options win over env, except CHAMVI_SANDBOX_PROVIDER, CHAMVI_SANDBOX_NAMESPACE, CHAMVI_SANDBOX_IMAGE, CHAMVI_SANDBOX_IMAGES (over allowImage) and CHAMVI_DEPLOYMENT, which win over the sandbox options. Tokens and hooks ​

AppToken holds the container keys, ModuleName the built-in names, AUTHENTICATOR_ORDER the chain order (static tokens 0, authup 10, oidc 20, lowest first):

ts
/*
 * Copyright (c) 2026.
 * Author Peter Placzek (tada5hi)
 * For the full copyright and license information,
 * view the LICENSE file that was distributed with this source code.
 */

import { TypedToken } from 'eldin';
import type { AppTokens } from './types.ts';

function token<K extends keyof AppTokens>(key: K): TypedToken<AppTokens[K]> {
    return new TypedToken<AppTokens[K]>(`chamvi.${key.toLowerCase().replace(/_/g, '-')}`);
}

/**

Agent folders ​

ts
function loadAgent(dir: string, options?: LoadAgentOptions): Promise<LoadedAgent>;
function loadAgents(root: string, options?: LoadAgentOptions): Promise<LoadAgentsResult>;
function listAgentFolders(root: string): Promise<string[]>;
function hashAgentFolder(dir: string): Promise<string>;

loadAgent builds one folder's agent from its agent.ts (see the rule) and its content hash, and throws InvalidAgentDefinitionError naming the file relative to the agents dir. loadAgents loads every folder listAgentFolders names (the direct subfolders not starting with . or _, node_modules left out, in code-point order) and returns the failures as issues instead of throwing. hashAgentFolder is sha256 (hex) over every file below the folder, dot-entries skipped, by relative POSIX path. loadAgent also refuses a folder that changed while it was read (<agent>: changed while loading; load it again.), a node_modules folder in the agent folder or the agents dir, and a JavaScript file (.js, .mjs or .cjs) anywhere in the folder. The default reader transpiles agent.ts and every .ts/.mts file it imports on every load and resolves @chamvi/*, ai and @ai-sdk/* to the copies @chamvi/app resolves. The loader holds the only jiti and locter imports of chamvi.

Models ​

ts
const BUILTIN_PROVIDERS: readonly BuiltinProvider[]; // anthropic, openai, google, mistral, xai: the implicit providers

See Pick a Model for the whole picture. createApp({ model, providers, models }) sets the default model, the named providers and AI SDK provider objects by id; CHAMVI_MODEL, CHAMVI_CONFIG_FILE (else ./chamvi.json) and CHAMVI_PROVIDER_<NAME>_* set the same from the deployment. Sources, highest first: env, the config file, code; providers merge per name and field, a higher source with another type replaces the provider, a CHAMVI_PROVIDER_<NAME>_* variable without _TYPE needs another source to declare <name>, and a declared provider replaces the implicit one of its name. models wins over everything for its ids (no package imported), the test seam.

Model strings are split at the first /. Every provider gets an explicit key and base URL (the type's public URL when none is set), read from the app's env only, never from process.env behind its back; { file } secrets are read relative to the working directory with one trailing newline trimmed. The config file refuses a literal apiKey and literal credential headers. Errors name the variable or file field and never echo a value: Agent "<a>" uses provider "<p>", which is not configured. Set CHAMVI_PROVIDER_<P>_TYPE and CHAMVI_PROVIDER_<P>_API_KEY, or declare it in chamvi.json., Provider "<p>" (<type>) needs CHAMVI_PROVIDER_<P>_API_KEY., Provider type "<type>" needs package <pkg>. Nothing reads or sets the AI SDK's global default provider, so two apps in one process keep their own providers.

/** createApp's `models`: providers by id, as `createProviderRegistry()` takes them. */
export type ModelProviders = Parameters<typeof createProviderRegistry>[0];

/** What a provider is built with: the AI SDK package and factory behind a provider name. */
export type ProviderType = 'anthropic' | 'openai' | 'openai-compatible' | 'google' | 'mistral' | 'xai' | 'gateway';

/** A secret: a literal, an env variable of the app's env, or a file (relative to the cwd, one trailing newline trimmed). */
export type SecretValue = string | { env: string } | { file: string };

/** A named provider, as createApp's `providers` and the config file declare it. */
export type ProviderConfig = {
    type: ProviderType;
    apiKey?: SecretValue;
    /** Absolute http(s) URL without credentials, query or fragment; default the type's public URL. */
    baseURL?: string;
    /** Header names match `^[a-z0-9]+(-[a-z0-9]+)*$` (lower-cased first). */
    headers?: Record<string, SecretValue>;
};

/** Where a setting came from: an env variable, the config file, createApp's options, or a bare provider variable. */
export type SettingSource = 'env' | 'file' | 'code' | 'implicit';

/** A provider after merging code, config file and env: secrets resolved, header names lower-cased. */
export type ProviderSettings = {
    name: string;
    type: ProviderType;
    apiKey?: string;
    baseURL?: string;
    headers: Record<string, string>;
    /** Where each field came from. */
    sources: {
        type: SettingSource;
        apiKey?: SettingSource;
        baseURL?: SettingSource;
        headers: Record<string, SettingSource>;
    };
};

/** The app's model settings: the default model and the providers that were read without an issue. */
export type ModelSettings = {
    model?: { ref: ModelRef; source: SettingSource };
    providers: ReadonlyMap<string, ProviderSettings>;
    /** The config file read (absolute), when one was. */
    configFile?: string;
};

/** A problem found while reading the settings; never holds a secret value. */
export type ModelIssue = {
    provider?: string;
    message: string;
};

/** A built-in provider id, its package and the bare env variables it reads. */
export type BuiltinProvider = {
    /** The provider name, the part of a model string before the first `/`. */
    id: string;
    /** The npm package. */
    package: string;
    /** The factory the package exports. */
    factory: string;
    /** The env variable holding the API key. */
    apiKey: string;
    /** The env variable holding a base URL, when the provider reads one. */
    baseUrl?: string;
};

app.check({ env? }) (chamvi start --check) runs the same settings through the real start path without starting anything or writing to the store; see Check before you deploy.
