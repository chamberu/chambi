Self-hosted agents

Agents that keep the keys.

You write the agent with the AI SDK. chamvi queues its runs, checkpoints every step, pauses for approvals and resumes interrupted runs, in your own Node process and database.

What the AI SDK leaves out

The layer between a model call and an agent you can trust.

  • 01

    One contract for every channel

    A webhook, a cron tick, a GitHub delivery or a manual call becomes the same envelope and the same queued run, and tools answer through the same channels. Idempotency keys turn redeliveries into the existing run; concurrency keys keep two runs for one issue apart.

    dispatch({ idempotencyKey })

  • 02

    Runs survive restarts

    A checkpoint after every step. drain() hands unfinished runs back, and recover() continues them from the latest checkpoint on any replica, without applying a recorded effect twice.

    drain() → recover()

  • 03

    Ask before acting

    A tool that needs a human awaits approve() and the run pauses in waiting. Approve or deny it an hour or a day later, from any replica; the call then runs again with the decision.

    await approve(ctx, { title })

How a run flows

Seven statuses, one store.

Every run lives in your store, from dispatch to its final status. Whatever stops it halfway, the next execution starts from the latest checkpoint.

Fires cron.on() subscriptions once per tick across replicas, with overlap policies, timezones and one-shot jobs.
