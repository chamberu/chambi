# Testing

## Setup

- **Runner**: Vitest (`vitest --config test/vitest.config.ts --run`), per package.
- **Location**: `packages/<name>/test/unit/<module>/*.spec.ts`, mirroring `src/` (e.g. `engine/lifecycle.spec.ts`); shared helpers in `packages/<name>/test/utils/`.
- **Coverage**: `npm run test:coverage` (v8, thresholds 80% for branches, functions, lines, statements).

```bash
npm run test                                       # all packages via nx
npx nx run @chamvi/core:test                     # one package (or @chamvi/test-kit)
cd packages/core && npx vitest --config test/vitest.config.ts --run test/unit/engine/dispatch.spec.ts   # one file
cd packages/core && npx vitest --config test/vitest.config.ts   # watch mode
```

Only `test/unit/**/*.{test,spec}.{js,ts}` is picked up; a new test directory needs the `include` glob widened. CI runs `npm run test`, not `test:coverage`, so the coverage thresholds do not gate merges.

## Conventions

- Tests import the public API by package name (`@chamvi/core`, `@chamvi/test-kit`); each `vitest.config.ts` aliases them to the packages' `src/index.ts`, so tests run against sources, not `dist`. Internals (e.g. `src/effect/helpers.ts`, `src/store/index.ts`) are imported by relative path.
- Assert the expected behaviour from the module contract, not what the implementation happens to do; a failing test may be a real bug.
- Use `MemoryStore` and `mockModel(responses)` (`test/utils/mock-model.ts`, scripted `MockResponse`s per model call) instead of mocking internals. Prefer fakes over `vi.mock()`.
- Time goes through the injectable `IClock`: pass a `ControllableClock` to the engine and store and advance it, never real timers. Core's tests take it from `test/utils/clock.ts`; every other package takes it from `@chamvi/test-kit`.
- `@chamvi/store-typeorm` tests need Docker: `test/global-setup.ts` starts `postgres:18-alpine` with testcontainers once per run, and each spec file creates its own database (`createTestDataSource()` in `test/utils/database.ts`, sessions in `TimeZone=America/New_York`). Without Docker the Postgres suites skip with a warning locally and fail when `CI` is set.
- hubwire (croner) takes no `IClock`. Cron tick logic (`@chamvi/channel-cron`) is tested by calling `fireCronSubscription` or `buildComponentOptions(...).run({ scheduledAt })` directly; only tests that need hubwire to fire use `vi.useFakeTimers()` (always restored in `afterEach`), with a `MemoryStore()` on the default `systemClock`, which follows the faked `Date`. `packages/channel-cron/test/unit/hubwire.spec.ts` pins the upstream contract (lock, `scheduledAt`, timezone, DST, the expression croner and cron-parser disagree on).
- `@chamvi/github` tests (the tools and the channel) never reach GitHub: `createGithubApp({ fetch })` takes the in-process fake `createFakeGithub({ appId, slug?, clock })` from `@chamvi/test-kit` (`github-fake/`: an RSA key pair, JWT and installation-token checks on the fake's `ControllableClock`, routes over mutable `issues`/`comments`/`labels`/`pulls`/`files`/`releases`/`repositories`/`checkRuns`/`statuses`/`branches`/`rules` maps (issue and pull request creation, the merge, check runs, the combined status, branch protection and rules), `appInstallations` (`GET /app/installations` with the App JWT; `GET /installation/repositories` answers the `installations` entries of the token's installation), `installations` (`owner/repo` to an installation id for `GET /repos/:owner/:repo/installation` with the App JWT; a token of another installation gets 404 on that repository's routes) and `users` (`GET /users/:login` without credentials), `route()` to add or override one, `failNext()` for a one-shot error, `requests` to assert on; a request whose signal aborts, also while a route handler is pending, rejects with the signal's reason). `test/utils/app.ts` builds engine, http app (with the channel mounted) and fake (`createGithubTestApp`) and posts signed deliveries to `/channels/github` (`deliver`); `test/utils/tools.ts` calls tools with a `ToolContext` and call options as the AI SDK does.
- `@chamvi/tool-web` tests never reach the network: `createFakeWeb()` (`test/utils/web.ts`) is a hapic client over an in-memory `fetch` (`routes` per URL, `calls`), a fake `lookup` (`dns` per host, a public address by default, `lookups`) and route helpers (`html`, `text`, `json`, `redirect`, `hang`); the timeout test arms `hang`, waits for the call, then advances the `ControllableClock`.
- `@chamvi/channel-openclaw` tests never reach OpenClaw: `openclawChannel({ fetch })` takes the in-process gateway of `test/utils/openclaw.ts` (`createFakeOpenclaw({ token, hooksPath?, clock? })`: the verified hooks contract (bearer token, `message` and a concrete `channel`/`to`, a replay of the same key and body for 5 minutes, a new run for another body), `requests`, `dispatched` (admitted runs), `failNext(status, headers?, body?)` (`$MESSAGE` echoes the message), `loseNextResponse()`, `hangNext()`). Timeout tests arm the hang, `await vi.waitFor()` until the request arrived, then `clock.advance()` (it fires only timers that exist). Both channels with `out` pin "one send per approval" (and the approval message without a token) against a real `Engine` on a `ControllableClock` (`test/unit/channel/engine.spec.ts`, driven with `tick()` and `idle()`).
- Sandbox providers run `describeWorkspaceContract(name, factory, { find? })` from `@chamvi/test-kit` (`factory({ runId? })` returns a fresh repo-less workspace; the suite disposes it; `find` is a second provider instance's `find`, which runs the section that drops a handle and finds the workspace again with its files). It is the documented exception to the `IClock` rule: it runs real processes with short real timeouts (timeouts, process-group kills, floods), as does the Docker suite. `@chamvi/sandbox`'s tests use a private `test/utils/clock.ts`, scripted workspaces (`test/utils/workspace.ts`), a fake provider (`test/utils/provider.ts`) and a fake transport (`test/utils/transport.ts`). Checkouts use `createGitFixture(files)` (a temp repository, branch `main`, tag `v1`; `fixture.git(...args)` adds commits and branches with the fixture's identity) with `allowFileRepos: true`. Git credentials: the manager specs (`credentials.spec.ts`, `git-tools.spec.ts`) drive scripted workspaces (`createFakeProvider({ onExec })`): credential installation is recognized by `INSTALL_CREDENTIALS_SCRIPT`, structured Git calls by `GIT_AUTH_SCRIPT`; `test/unit/git/scripts.spec.ts` runs the helper scripts with real `sh` and a fake `git` on `PATH`. `@chamvi/sandbox-local`'s `test/unit/provider/git.spec.ts` runs the whole flow against a private https host: `startGitServer()` (`test/utils/git-server.ts`, a self-signed loopback certificate from `openssl`, `git http-backend` behind basic auth, trusted through `GIT_SSL_CAINFO` in the workspace env), skipped locally when `openssl` or `git http-backend` is missing, never in CI.
- `@chamvi/sandbox-docker` tests need Docker: `test/global-setup.ts` gates on dockerode `ping()` (skip with a warning locally, fail when `CI` is set), builds `images/sandbox-dev` as `chamvi/sandbox-dev:test` once per run and removes leftover `test-` run containers and the test cache volume `chamvi-sandbox-cache-test` at the end (specs build providers with `dockerOptions` from `test/utils/docker.ts`, which names that shared test volume, so the shared-cache specs never touch an operator's volume; the image probe spec builds `test/fixtures/no-git` on the test image, offline, and the entrypoint spec `test/fixtures/entrypoint` (`ENTRYPOINT ["git"]`)); `describeDocker()` (`test/utils/docker.ts`) skips a suite without Docker. Tests that reach the network (clone a public repository, pull an image) are skipped when `CHAMVI_OFFLINE` is set. `test/unit/coding.spec.ts` runs `codingTools()` (a devDependency on `@chamvi/coding`) in a `sandbox-dev` container: dash as `/bin/sh` (and as the inner shell through a `bash` shim), ripgrep and GNU `timeout`, which the macOS host of the local provider lacks. `@chamvi/coding`'s own tests run on the local provider, whose host `PATH` has no ripgrep, so they pin the `git grep` and `grep` engines.
- `@chamvi/sandbox-k8s` tests never reach a cluster: the provider takes a fake `IPodClient` (`test/utils/client.ts`) on a `ControllableClock`, and `createPodClientFrom()` is tested with fake `core`/`exec` parts. A real cluster is a manual check (kind, a least-privilege service account, the plan's steps).
- Every store implementation runs `describeStoreContract()` from `@chamvi/test-kit` (the `MemoryStore` run lives in `packages/test-kit/test/unit/memory-store.spec.ts`).
- `test/unit/smoke.spec.ts` checks that the package entry resolves.
- `test/unit/exports.spec.ts` pins the public exports; `test/unit/readme.spec.ts` runs `test/fixtures/readme-example.ts` and checks that the package's `README.md` contains that file verbatim. Change the example in the fixture, then copy it into the README.

## App and CLI (`@chamvi/app`, `@chamvi/cli`)

- `@chamvi/app` tests run modules on `createHarness()`/`buildHarness()` (`test/utils/harness.ts`, an alias of the public `createModuleHarness()`/`buildModuleHarness()` from `@chamvi/app/testing`: an orkos `Application` over a fresh eldin container with `AppToken.CONTEXT` registered, the modules wrapped like the app does, `setup()` also running the start steps, `reported` collecting `context.report()`) or a whole `createApp()` with `start({ env })`; real loopback ports come from `freePort()` (`test/utils/port.ts`), log lines from `createRecordingLogger()` (`test/utils/logger.ts`). `test/unit/readme.spec.ts` starts the README example with `ANTHROPIC_API_KEY` in its `env` (it builds the implicit `anthropic` provider the example's default model names, through the `@ai-sdk/anthropic` devDependency; nothing calls the model); a spec that starts an app with a string model passes a key or `models`, since no global provider exists any more. The Postgres suites (`describePostgres`, a database per test from `createTestDatabaseUrl()` in `test/utils/database.ts`) need Docker like `@chamvi/store-typeorm`: `test/global-setup.ts` starts `postgres:18-alpine` with testcontainers, skipping with a warning locally and failing when `CI` is set. `test/unit/app/check.spec.ts` drives `IApp.check()` over a `MemoryStore` behind a recording `Proxy` (every call not named `get*`/`list*`/`read*` is a write) to pin that a check writes nothing; the harness takes `check` and `job` (copied into the context), and `test/utils/agents-dir.ts` passes them on.
- The optional modules' specs live in their feature package (`test/unit/module/`) and run on `createModuleHarness()` from `@chamvi/app/testing` with the built-ins they need, asserting a contribution (a channel in `AppToken.CHANNELS`, a route) through `harness.container` and a refused provide through `harness.reported` (never a rejected `setup()`); `test/unit/context/` pins a context pair against a real `Engine` run. Their vitest config aliases `@chamvi/app`, `@chamvi/app/testing`, `@chamvi/http`, `@chamvi/channel-cron`, `@chamvi/store-typeorm`, the package itself and its own `/module` to sources. `@chamvi/sandbox` still never imports `@chamvi/test-kit`.
- `test/unit/loader/identity.spec.ts` spawns `test/fixtures/identity/run.mjs` on the built `@chamvi/app` and `@chamvi/core` (a folder tool in a temp dir outside the tree injects a module's context key), so `nx` runs `@chamvi/app:test` after its build (`dependsOn: ["build"]`); running that spec by hand needs `npm run build` first. `test/utils/agents-dir.ts` builds the agents module harness for the newer agents specs.
- `@chamvi/cli` command tests call `runCli(argv, context)` with the fake process of `test/utils/process.ts` (signals, a `ControllableClock`, recorded exit codes, `linkToParent` calls) over the apps in `test/fixtures/` (`app`, `failing`, `hang`, `slow`, `keyless`, `broken`). The `test/unit/bin/` specs spawn the built `dist/cli.mjs` (`spawnCli()` in `test/utils/spawn.ts`), which imports the built `@chamvi/app`, so `nx` runs `@chamvi/cli:test` after its build (`dependsOn: ["build"]`); running vitest by hand needs `npm run build` (at least `@chamvi/app` and `@chamvi/cli`) first. `test/unit/commands/start-check.spec.ts` pins `start --check` (exit codes, one stderr line per folder issue, nothing listening).

## Dashboard (`@chamvi/ui`)

- `nx` runs `@chamvi/ui:test` after its build (`dependsOn: ["build"]`): `readme.spec.ts` serves the real `dist/app`. Running vitest by hand needs `npx nx run @chamvi/ui:build` first.
- Unit tests live in `test/unit/routes/` (the route against `test/fixtures/build/`, a fake build with the config marker) and `test/unit/app/<module>/` (the SPA modules, in Node: fake `fetch` (`test/utils/fetch.ts`), fake client (`test/utils/client.ts`), in-memory `Storage` (`test/utils/storage.ts`), fake timers for the poller (`test/utils/timers.ts`), composables run inside `effectScope()`, routers on `createMemoryHistory`). The vitest config has the Vue plugin so a module that lazily imports a `.vue` file loads; `app/tsconfig.json` (vue-tsc) typechecks `test/unit/app`.
- e2e: `npm run build && npm run test:e2e -w @chamvi/ui` (once: `npx playwright install chromium`). Playwright starts `node test/e2e/demo/server.ts` (type stripping, so Node >= 22.18 or 24; no `enum`, explicit `.ts` imports) on port 4173 against the built packages and reuses a running one outside CI. The specs fail on any console error, which is how a CSP violation shows up. `test/e2e/**` never runs under vitest (its `include` is `test/unit/**`).

## Skills preparation (`@chamvi/skills`)

Tests use the real pinned SDK and `createGitFixture()`, with no external network or providers. They cover source confinement with real committed nested aliases/external files, linked discovery containers and unrelated source links; a delegating SDK spy proves rejection before discovery, with no verifier and prior output/cleanup intact. They also cover exact cloned commits (including SHA-shaped branches), duplicate/missing selection, retained assets, staged hash verification, managed replacement/rollback, same-target exclusion and cwd stability. The typed README consumer is reused unchanged in a real `prepareSkills` -> `hashSkillBundle`/`loadSkillBundles` -> `Engine` proof of metadata-only initial context and pinned body/reference results. Real remote selected-profile preparation is a separate manual proof.

The metadata process specs delegate normal commands to real Git and use finite Git executables for output floods, silent nonzero exits, external SIGTERM and continuously emitting commands that ignore SIGINT. A delegating child-process test wrapper compresses only an exact 30000ms `execFile` deadline, preserving the real child and promisified output. Signal-handler and completion markers verify SIGTERM termination before voluntary completion, without tight elapsed-time assertions. Tests reject before discovery, retain the previous corpus and check clone/staging/lock cleanup and cwd. Test-kit process specs cover exact 1 MiB allowances separately per stream/command, SIGINT-resistant overflow termination, raw NUL/newline output, silent `git diff --quiet` failure, external signals, subsequent command recovery and replacement of hostile inherited environment/config with the fixture identity.
